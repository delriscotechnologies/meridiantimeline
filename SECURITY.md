# Security Policy

## Supported Version

Security fixes are applied to the latest version on the `main` branch.

## Reporting a Vulnerability

Use GitHub private vulnerability reporting from the repository's **Security** tab when available.

Do not include real investigation logs, usernames, email addresses, IP addresses, device names, tenant information, authentication details, file hashes from private cases, or generated workbooks in a public issue.

Include the affected version, sanitized reproduction steps or sample data, expected behavior, actual behavior, and potential impact.

## Security Model

meridiantimeline is a local investigation utility. It processes files selected by the analyst and writes an Excel workbook to a location selected by the analyst.

The script:

- does not upload logs or connect to a remote service
- does not request or store passwords, tokens, or other credentials
- does not modify the selected source files
- accepts TXT and CSV only as delimited tables
- opens XLSX workbooks as read-only with link updates disabled
- disables Excel automation macros before opening or creating workbooks
- formats generated cells as text and neutralizes values beginning with `=`, `+`, `-`, or `@` to reduce spreadsheet-formula injection risk
- calculates SHA-256 once for each imported source file
- rejects ambiguous and nonexistent daylight-saving timestamps instead of guessing
- limits each file to 100 MB and 200,000 rows
- does not use `Invoke-Expression` or execute content taken from imported logs

## Data Handling

Source logs and generated workbooks may contain sensitive identity, endpoint, network, authentication, and investigation data.

Store output workbooks only in approved locations. Apply the same access controls, retention requirements, and handling procedures used for the original evidence. Delete temporary or exported investigation data according to your organization's policy.

The SHA-256 recorded by the tool identifies the file that was processed at that time. It does not independently establish authenticity, acquisition history, or chain of custody.

## Operational Guidance

Run the tool only on trusted Windows systems and only with files you are authorized to analyze.

Microsoft Excel is used to read XLSX inputs and create the output workbook. Macros and external-link updates are disabled by the script, but untrusted Office files should still be scanned and handled according to your organization's endpoint and malware-analysis procedures.

Verify the source timezone selected for each file. Timestamps with explicit offsets are honored, while timestamps without offsets depend on the analyst's selected source timezone. Review all entries in **Import Issues** before relying on the timeline.

`What Happened` is a deterministic convenience summary for supported fields and Windows event IDs. It does not determine intent, compromise, severity, attribution, or causality.

Formula-safety controls apply to the workbook generated by meridiantimeline. Copying values into another spreadsheet, exporting them through another tool, or removing text formatting can change how downstream software interprets those values.

Raw event snapshots longer than 30,000 characters are truncated in the generated workbook. Use the recorded source file, source row, and SHA-256 to review the complete evidence.
